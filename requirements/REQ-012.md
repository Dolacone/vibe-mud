# REQ-012 - Mobile frontend shell

## 情境

> 已登入頁面需要共用的手機 App Shell。各主分頁的內容由獨立 REQ 定義，避免共用框架與遊戲功能互相綁定。

## 行為

1. 已登入介面必須使用 mobile-first 的單一 App Shell。
2. App Shell 頂端必須固定顯示兩排核心狀態，且不得隨主分頁切換。
3. 第一排必須依序顯示目前 AP、目前 HP 與 `Weight <current>/<max>`，不得顯示玩家名稱。
4. HP 尚未實作時，第一排必須顯示明確 placeholder，不得顯示虛構數值。
5. 第二排必須依固定順序顯示玩家持有量大於 0 的 Resource，且最多包含既有 8 種 Resource。
6. 兩排核心狀態都必須維持單行，不得自動換行。
7. 任一核心狀態列超過可用寬度時，玩家必須能在該列水平 swipe 查看後續資訊。
8. 核心狀態列的水平 swipe 不得造成整個頁面水平溢出，也不得阻止主內容垂直捲動。
9. App Shell 底部必須固定提供 `地圖`、`地區`、`道具`、`角色` 四個主分頁。
10. 切換主分頁不得重新登入或遺失最新 authoritative player state。
22. 前端只能顯示後端依 REQ-018 回傳的 Action、target、method 與 recipe，不得自行補回不可用選項。
23. Action 完成後，頂端核心狀態與目前主分頁必須使用最新後端狀態更新，不得要求完整頁面重新載入。
24. 個別主分頁載入或操作失敗時，頂端核心狀態與底部主分頁必須保持可見。
25. `Weight` 小於或等於上限 75% 時必須顯示綠色，超過 75% 且小於或等於上限時必須顯示黃色，超過上限時必須顯示紅色。
26. `地圖` 與其他主內容不得重複顯示 header 已提供的目前重量與重量上限。
