# REQ-013 - Ground asset transfers

## 情境

> 玩家需要把持有的 Item 與 Resource 留在目前 Location，或撿取其他玩家留下的資產。Pickup 與 Drop 只搬移既有價值，不增加世界資產，因此不屬於 Action，也不消耗 AP。

## 行為

1. 每個 Location 必須具有獨立的地面 Item 與 Resource 狀態。
2. 地面資產不得限制總重量、quantity 或堆疊數量。
3. 地面資產不得具有 owner、存取權限或預留機制。
4. 玩家必須能查看目前 Location 的所有地面 Item 與 Resource quantity。
5. 玩家必須能指定正整數 quantity，將持有的有效或失效 Item Drop 至目前 Location。
6. 玩家必須能指定正整數 quantity，將持有的任意 Resource Drop 至目前 Location。
7. 玩家必須能指定正整數 quantity，Pickup 目前 Location 的有效地面 Item。
8. 玩家必須能指定正整數 quantity，Pickup 目前 Location 的任意地面 Resource。
9. Item 必須依 Location、Item type 與有效狀態合併 quantity。有效與失效 Item 不得合併。
10. Resource 必須依 Location 與 Resource type 合併 quantity，不得轉換成 Item。
11. Pickup 與 Drop 必須屬於 Transfer，不得視為 Action。
12. Transfer 成功或失敗時都不得消耗或恢復 AP。
13. Transfer 成功時，來源扣除與目的增加必須原子更新，且總 quantity 必須保持不變。
14. 玩家持有量或地面持有量不足，或玩家嘗試 Pickup 失效 Item 時，Transfer 必須失敗，且所有狀態保持不變。
15. 玩家不得 Pickup 或 Drop 目前 Location 以外的地面資產。
16. 多位玩家同時 Pickup 時，地面 quantity 不得低於 0，且成功取得的總量不得超過原有 quantity。
17. 地面資產與 Transfer 結果必須在重新整理、重新登入及其他玩家讀取後保持一致。
18. 前端必須用表格顯示地面 Item 與 Resource。有效 Item 與 Resource 必須提供 Pickup。玩家持有的有效或失效 Item 與 Resource 必須提供 Drop。
19. Transfer 完成後，前端必須顯示後端回傳的最新玩家與地面狀態。
20. Backend 必須把 Transfer access 與結果寫入 stdout，並包含 user ID、Location、asset type、asset identifier、quantity、結果與 request ID。
21. Backend log 不得包含 credentials、session、OAuth 資料、cookie 或未處理的原始輸入。
22. Item Transfer 必須指定 `active` 或 `expired` 堆疊。Resource Transfer 不得指定 Item 狀態。
23. Item 狀態缺少、不合法或不適用時，Transfer 必須失敗，且所有狀態保持不變。
