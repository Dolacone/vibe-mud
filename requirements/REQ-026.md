# REQ-026 - Monster combat

## 情境

> 玩家需要主動攻擊 Location 累積的 Monster，也可能在移動時遭到攔截。戰鬥必須由後端依相同規則完整結算，保存 HP、Monster 數量與掉落結果。

## 行為

1. 玩家 HP 上限、HP 恢復間隔與空手攻擊力必須由 database definition 提供，不得寫死於戰鬥流程。
2. MVP 玩家 HP 上限必須為 100，每 60 秒恢復 1 HP，空手攻擊力必須為 3。
3. 玩家 HP 狀態只能保存恢復至滿 HP 的 UTC Unix seconds timestamp，不得保存目前 HP 數值。
4. 系統必須依 backend current timestamp 計算目前 HP，且非戰鬥狀態的 HP 必須介於 1 至 100。
5. 既有玩家與新玩家第一次取得 HP 狀態時必須具有 100 HP。
6. 玩家主動執行 `attack` 必須消耗 30 AP。攔截觸發的戰鬥不得消耗 AP。
7. 主動 `attack` 只能在目前 Location 至少具有 1 隻 Monster 且玩家具有 30 AP 時執行。
8. 戰鬥開始時，系統必須依目前 Location 的 encounter weight 抽選一種 Monster type，並載入該 type 的 HP、攻擊力與掉落規則。
9. 戰鬥必須在單次 request 內由 backend 自動結算，不得等待玩家逐回合輸入。
10. 每回合必須由玩家先攻擊一次。Monster HP 歸零時，本回合必須立即結束，Monster 不得反擊。
11. 玩家攻擊後 Monster 仍存活時，Monster 必須攻擊玩家一次。玩家 HP 歸零時，戰鬥必須立即結束。
12. 每次攻擊傷害必須在 `ceil(攻擊力 × 0.5)` 至 `floor(攻擊力 × 1.5)` 之間均勻抽選整數，且傷害最低為 1。
13. 玩家與 Monster 必須使用相同的傷害公式，且戰鬥不得套用防禦、減傷、命中、閃避、暴擊或技能。
14. Forest Rat 必須使用正整數 type ID，並定義 10 HP 與 2 攻擊力。
15. Monster HP 歸零時，玩家必須獲勝。系統必須把目前 Location 的 Monster 總數減少 1，並分別依每項掉落機率抽選掉落物。
16. Forest Rat 必須具有 Rat Tail 掉落規則，每次勝利有 50% 機率產生 1 個 Rat Tail Item。
17. Rat Tail 必須是單位重量 1 的 Item，並依 REQ-015 取得完整耐久時間及合併至正確 Inventory 堆疊。
18. 玩家 HP 歸零時，Monster 必須獲勝。系統必須把玩家 HP 設為 1，不得減少 Monster 總數或產生掉落物。
19. 主動 `attack` 開始後，無論勝負都必須扣除完整 30 AP。攔截戰鬥無論勝負都不得修改 AP。
20. 戰鬥結束時，玩家 HP、AP、Monster 總數與掉落物必須在同一 transaction 內保存。
21. 主動 `attack` 因 AP 不足、Monster 數量為 0、輸入不合法或 Action 不可用而失敗時，所有玩家與世界狀態必須保持不變。
22. 多位玩家同時攻擊最後一隻 Monster 時，最多只能有一位玩家開始戰鬥並取得勝利掉落。
23. 戰鬥回應必須依發生順序列出每次攻擊的攻擊者、傷害與目標剩餘 HP。
24. 戰鬥回應必須包含 Monster 顯示名稱、勝負結果、掉落物，以及最新玩家 HP、AP、Location 與 Monster 總數。
25. 主動攻擊完成後，前端必須顯示戰鬥過程與結果，不得要求重新載入頁面。
26. 移動遭到攔截時，前端必須顯示相同格式的戰鬥過程與結果，不得要求重新載入頁面。
27. 重新整理、重新登入或重啟 backend 後，系統必須顯示依保存 timestamp 計算的目前 HP，以及已保存的 Monster 與掉落結果。
28. Backend 必須把每次 type 抽選、傷害、掉落、HP、AP 與 Monster 數量計算結果寫入 stdout，並包含 user ID、Location、action、outcome 與 request ID。
29. Backend log 不得包含 credentials、session、OAuth 資料、cookie、secrets 或未處理的原始輸入。
30. `attack` 必須屬於 Action，並透過專用 endpoint 接受空 JSON object。前端不得指定 Monster type、AP 成本、傷害、掉落或戰鬥結果。
31. Backend 必須把 `attack` 與攔截戰鬥的 success 或 failure access 結果寫入 stdout，並包含 user ID、Location、action、outcome、拒絕原因與 request ID。
