# REQ-008 - Action: convert

## 情境

> 玩家需要在任何 Location 使用後端定義的 Convert method，把 Active 原物料轉成 Resource，並有機會取得 Essence。每個 method 的 AP 成本、處理量與產出必須分開定義，讓後續平衡調整不需要改變 Convert 規則。

## 行為

1. 已登入玩家必須能在任何 Location 使用徒手 Convert method。
2. 每個 Convert method 必須具有穩定 identifier 與顯示名稱。
3. 每個 Convert method 必須分別定義 AP 成本、input Item、單次 input quantity 上限、output Resource、每單位 input 的 Resource quantity、Essence Item、Essence 機率與 Essence quantity。
4. 前端必須顯示後端提供的 Convert method、AP 成本、單次 input quantity 上限、Resource 產量與 Essence 機率。
5. 玩家必須選擇後端提供的 Convert method 與不超過該 method 上限的正整數 quantity。
6. 每次 Convert 必須扣除該 method 定義的一個完整 AP 成本，實際 quantity 不得改變該次 AP 成本。
7. Convert 成功時，必須依實際 quantity 扣除 Active input Item，並依每單位產量增加 output Resource。
8. 每個被 Convert 的 input Item 必須分別依該 method 定義的機率判定 Essence 結果。
9. Convert 取得的 Essence 必須加入玩家 Inventory。
10. AP、input Item、output Resource 與 Essence 結果必須原子更新。
11. AP、Active input Item 或 method 使用條件不足時，Convert 必須失敗，且所有狀態保持不變。
12. 後端必須拒絕不存在的 method、非正整數 quantity、超過 method 上限的 quantity、錯誤格式與未支援欄位。
13. 徒手 Wood Convert method 必須消耗 30 AP，單次最多處理 3 個 Wood，每個 Wood 產出 1 Wood Resource，並各自具有 10% 機率產出 1 個 Wood Essence T1。
14. Convert 結果必須在重新整理與重新登入後保持一致。
15. 後端必須記錄 user ID、Action、method、quantity、Resource 產量、Essence 判定結果、結果與 request ID。
16. Log 不得包含 credentials、session、OAuth 資料、cookie、secret 或未處理的原始輸入。
