# REQ-016 - Building extension lifecycle

## 情境

> 完成的 Building 具有 extension slot，但玩家尚未能安裝 Package、共同投入 AP、完成 extension 或拆除 extension。這些規則必須適用於所有 Building extension，不能綁定單一功能。

## 行為

1. 每個 Building extension definition 必須具有穩定 identifier、顯示名稱、tier、Package Item 與施工所需 AP。
2. 每個 completed Building 必須依 Building 建立時保存的 extension slot 數量提供空 slot。
3. Building owner 必須能把 definition 指定的 Active Package Item 安裝至自己目前 Location 的 completed Building 空 slot。
4. 安裝成功時，系統必須消耗 Package Item，並在指定 slot 建立 progress 0 的施工中 extension。
5. 安裝後的 extension 必須保存 definition identifier、顯示名稱、tier 與建立時的施工所需 AP。
6. Package Item 扣除與施工中 extension 建立必須原子更新。
7. Package Item 不足、Building 不符合條件、slot 已占用或 definition 不存在時，安裝必須失敗，且所有狀態保持不變。
8. 同一 Location 的所有玩家都能對施工中的 extension 投入自己的正整數 AP。
9. 系統必須以剩餘施工 AP 限制實際投入量，且只能扣除實際投入量。
10. AP 扣除與施工 progress 增加必須原子更新。
11. AP 不足、玩家不在同一 Location、extension 不在施工中或輸入不合法時，施工必須失敗，且所有狀態保持不變。
12. progress 達到施工需求時，extension 必須立即 completed。
13. Extension completed 前不得提供其功能。
14. 同一 Location 的所有玩家都能使用 completed extension 提供的功能。
15. Building owner 必須能拆除自己 Building 中施工中或 completed 的 extension。
16. 拆除 extension 時不得返還已消耗的 Package Item 或已投入 AP。
17. Extension 被拆除後，其 slot 必須恢復為空。
18. Extension、施工 progress 與 slot 狀態必須在重新整理與重新登入後保持一致。
19. 前端必須顯示空 slot、extension 顯示名稱、tier、施工狀態、progress、所需 AP 與玩家可用操作。
20. 後端必須記錄 user ID、Building、extension、操作、AP、結果與 request ID。
21. Log 不得包含 credentials、session、OAuth 資料、cookie、secret 或未處理的原始輸入。
