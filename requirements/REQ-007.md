# REQ-007 - Action: convert

## 情境

> 玩家可以在 `forest_edge` 採集 `Wood` item，但 collected item 尚未能轉換為可累積的 Resource balance。玩家返回 `camp` 後缺少消耗 Inventory 並取得 Resource 的 Action。

## 行為

1. 已登入玩家位於 `camp` 時，必須能透過前端執行 `convert` Action。
2. `convert` 成功時，必須消耗 1 AP 與 1 個 `Wood` item，並增加 1 Resource。
3. 後端必須決定允許的 Location、input item、input quantity、Resource 產量與 AP 成本，前端不能指定或覆寫這些值。
4. Resource 必須保存為獨立於 Inventory item quantity 的持久化玩家 balance。
5. 尚未取得 Resource 的玩家必須擁有 0 Resource。
6. 玩家不在 `camp` 時，`convert` 必須失敗，且 AP、位置、Inventory 與 Resource balance 都保持不變。
7. 玩家沒有至少 1 個 `Wood` 時，`convert` 必須失敗，且 AP、位置、Inventory 與 Resource balance 都保持不變。
8. 玩家 AP 少於 1 時，`convert` 必須失敗，且 AP、位置、Inventory 與 Resource balance 都保持不變。
9. AP 扣除、`Wood` 扣除與 Resource 增加必須是同一個原子結果，系統不能保存部分結果。
10. 玩家轉換最後一個 `Wood` 後，Inventory 必須不再顯示 `Wood`。
11. 玩家重複成功執行 `convert` 時，系統必須持續扣除 `Wood` 並累加 Resource balance。
12. 玩家重新整理或重新登入後，系統必須顯示已保存的 Inventory 與 Resource balance。
13. `convert` 成功後，前端必須顯示更新後的 AP、Inventory 與 Resource balance。
14. `convert` 輸入格式錯誤或包含未支援欄位時，後端必須拒絕 Action，且 AP、位置、Inventory 與 Resource balance 都保持不變。
15. 後端拒絕不合法的 `convert` 時，必須將事件以 error outcome 寫入 stdout，並包含 user ID、Action、拒絕原因與 request ID；log 不得包含 credentials、session、OAuth 資料或未處理的原始輸入。
