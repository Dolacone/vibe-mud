# REQ-025 - Location Monster population

## 情境

> 每個 Location 需要自己的 Monster 生成規則與累積數量。系統必須依現實經過時間補算生成，並讓累積 Monster 影響主動攻擊與離開該 Location 的風險。

## 行為

1. 每個 Location 必須定義生成間隔秒數、單次生成機率、Monster 數量上限與單隻攔截機率。
2. 每個會生成 Monster 的 Location 必須用正整數外部鍵引用一種以上 Monster type，並為每種 type 定義正整數 encounter weight。
3. 系統必須依 Location 保存尚未抽選 type 的 Monster 總數與最近一次結算時間。
4. 每經過一個完整生成間隔，系統必須獨立抽選一次是否增加 1 隻 Monster。
5. 生成成功時，系統必須把該 Location 的 Monster 總數增加 1，但不得超過數量上限。
6. Monster 總數已達上限時，系統仍必須結算已經過的完整間隔，不得在數量下降後補抽先前略過的間隔。
7. 後端必須在讀取 authoritative Location 狀態、合法 `attack` 通過 AP 檢查後判斷 Monster 數量，或合法 `move` 判斷攔截前，依目前 UTC Unix seconds 結算並保存所有完整生成間隔。
8. Fly Machine 停止或沒有 request 的時間仍必須依 timestamp 納入下次結算，不得依賴背景排程。
9. Monster 生成時不得預先抽選 type。系統只能在戰鬥開始時依 encounter weight 抽選本次 Monster type。
10. 目前 Location 具有 `N` 隻 Monster 時，總攔截率必須為 `1 - (1 - 單隻攔截率)^N`。
11. 攔截只能由玩家嘗試離開具有 Monster 的目前 Location 觸發，目的地的 Monster 不得攔截本次移動。
12. `camp` 必須使用 1800 秒生成間隔、0% 生成機率、0 數量上限與 0% 單隻攔截率。
13. `forest_edge` 必須使用 1800 秒生成間隔、50% 生成機率、10 數量上限與 10% 單隻攔截率。
14. `forest_edge` 必須只抽選 Forest Rat，encounter weight 為 1。
15. 多個 request 同時結算、攻擊或攔截時，Location Monster 總數不得超過上限或低於 0，同一隻 Monster 不得產生多次勝利掉落。
16. 重新整理、重新登入或重啟 backend 後，系統必須保留 Location Monster 總數與結算時間。
17. Backend 必須把每次 Monster 生成與攔截計算結果寫入 stdout，並包含 Location、間隔數、機率、結算前後數量、outcome 與 request ID。
18. Backend log 不得包含 credentials、session、OAuth 資料、cookie、secrets 或未處理的原始輸入。
