# REQ-010 - Building construction

## 情境

> 玩家已能製作加工品，但目前不能將材料投入世界建築。遊戲需要讓玩家建立 Building Lv1，並讓同地點玩家共同投入 AP 完成施工。

## 行為

### Building recipe

1. `Building Lv1` 必須具有後端定義的 recipe。
2. Recipe 必須定義 inputs 與施工所需 AP。
3. 玩家必須能看到 recipe 的 inputs 與所需 AP。
4. Recipe 來源不屬於本 REQ。
5. 前端不能覆寫 recipe inputs 或所需 AP。

### 開始施工

6. 玩家可以在目前 Location 建造自己的 `Building Lv1`。
7. 每位玩家在同一 Location 最多擁有一座 Building。
8. 施工中的 Building 必須占用 Building 名額。
9. 開始施工時，系統必須一次扣除所有 inputs。
10. 扣除 inputs 與建立 Building 必須是原子結果。
11. 新 Building 必須標記為施工中。
12. 新 Building 的已投入 AP 必須為 0。
13. Inputs 不足時，系統不得修改任何狀態。
14. 玩家已有 Building 時，系統不得建立第二座。
15. Building 必須保存建立時的所需 AP。
16. Recipe 變更不能影響施工中的 Building。

### 共同施工

17. 同一 Location 的玩家都能看到施工進度。
18. 同一 Location 的玩家都能投入自己的 AP。
19. 玩家可以選擇本次投入的正整數 AP。
20. 不在同一 Location 的玩家不能投入 AP。
21. 系統必須以剩餘所需 AP 限制實際投入量。
22. 超額投入只能消耗剩餘所需 AP。
23. AP 低於實際投入量時，施工必須失敗。
24. AP 扣除與進度增加必須是原子結果。
25. 失敗時，AP 與 Building 進度必須保持不變。

### 完成結果

26. 已投入 AP 達到需求時，Building 必須立即完成。
27. Building 進度不能超過所需 AP。
28. 完成的 `Building Lv1` 具有一個空 extension slot。
29. 重新登入後，玩家必須看到已保存的狀態。
30. 完成後不能繼續投入 AP。
31. 本 REQ 不提供撤銷、拆除或 extension 安裝。

### 輸入與 Log

32. 後端必須拒絕不存在或不允許的 target。
33. 後端必須拒絕錯誤格式與未支援欄位。
34. 拒絕時，所有狀態必須保持不變。
35. Log 必須記錄 user ID、Action、結果與 request ID。
36. Log 不得包含 credentials、session、OAuth 或原始輸入。
