# REQ-009 - Action: craft

## 情境

> 玩家持有 Wood Resource，但目前無法消耗 Resource 製作加工品。遊戲需要一個固定配方，建立 Resource 消耗與加工品取得的完整循環。

## 行為

### Recipe 定義

1. 每個 recipe 必須具有穩定 identifier 與顯示名稱。
2. 每個 recipe 必須定義基本 AP 成本。
3. 每個 recipe 必須定義一種以上 Resource input。
4. 每個 recipe 可以定義零種以上 Item input。
5. 每個 recipe 必須明確定義 output Item 與 quantity。
6. Recipe output 不能從 recipe 名稱推導。
7. `Wood Component` recipe 必須消耗 10 Wood Resource 與 10 AP。
8. `Wood Component` recipe 不消耗 Item input。
9. `Wood Component` recipe 必須產出 1 個 `Wood Component` item。

### 操作

10. 玩家位於任何 Location，且後端依 REQ-018 回傳 `Wood Component` recipe 時，前端必須顯示並讓玩家選擇。
11. 玩家必須能透過前端執行 `craft` Action。
12. 前端只能提交後端提供的 recipe identifier。
13. 前端不能覆寫成本、inputs 或 output。
14. Inputs 與 AP 足夠時，recipe 必須成功。
15. 目前 recipe 不使用隨機成功機率。

### 成功結果

16. 成功結果必須原子更新 AP、Resource 與 Inventory。
17. 重複製作必須累加 `Wood Component` quantity。
18. 前端必須顯示後端回傳的最新玩家狀態。
19. 重新登入後，玩家必須取得已保存的狀態。

### 拒絕結果

20. 任一 Resource input 不足時，`craft` 必須失敗。
21. 任一 Item input 不足時，`craft` 必須失敗。
22. AP 不足時，`craft` 必須失敗。
23. 失敗時，所有玩家狀態必須保持不變。
24. 後端必須拒絕不存在的 recipe identifier。
25. 後端必須拒絕錯誤格式與未支援欄位。
26. 後端必須記錄拒絕原因、user ID 與 request ID。
27. Log 不得包含 credentials、session 或 OAuth 資料。
