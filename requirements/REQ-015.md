# REQ-015 - Item durability

## 情境

> Item 目前會永久維持有效。玩家需要看到 Item 隨現實時間失效，並在失效後保留可辨識的紀錄，避免資產無預警消失。

## 行為

### 耐久定義與狀態

1. 每種 Item 必須分別定義耐久時間上限。
2. 所有 Item 的耐久時間上限都必須為 1 小時。
3. 既有的有效 Item 必須在此功能部署時取得完整 1 小時耐久時間。
4. 任何成功操作新產生的 Item 必須取得該 Item 的完整耐久時間。
5. Item 剩餘耐久時間大於 0 時必須顯示為 Active。
6. Item 剩餘耐久時間到達 0 時必須顯示為 Expired，且不能修復或恢復為 Active。
7. Active 與 Expired Item 必須顯示為不同堆疊。
8. 玩家必須能看到每個 Item 堆疊的狀態與剩餘有效時間。

### 有效堆疊合併

9. 相同持有位置的同種 Active Item 必須合併為一個堆疊。
10. Active 堆疊合併時，結果剩餘時間必須等於各來源 quantity 乘以剩餘時間後的總和，再除以合併後總 quantity。
11. 合併後的剩餘時間必須向下取整至完整秒數。
12. Active Item 被部分 Transfer 時，來源與移出 quantity 必須保留 Transfer 當下的相同剩餘時間。
13. Active Item Transfer 至既有 Active 堆疊時，必須依相同的數量加權公式合併。

### 失效與刪除

14. Expired Item 必須從失效時間起保留 1 天。
15. Expired Item 保留期結束後必須永久刪除。
16. Expired Item 仍必須計入玩家的攜帶重量。
17. Expired Item 不得用於 Convert、Craft 或 Building inputs。
18. 相同持有位置的同種 Expired Item 可以合併為一個堆疊。
19. Expired 堆疊合併時，結果刪除時間必須採用所有來源中最晚的刪除時間。
20. Active Item 永遠不得與 Expired Item 合併。

### 顯示與紀錄

21. Inventory 與地面都必須顯示尚在保留期內的 Expired Item。
22. 前端必須顯示 Expired Item 的剩餘保留時間，且不能提供會使用該 Item 的操作。
23. 後端必須將 Item 耐久計算與失效清理結果寫入標準輸出。紀錄必須包含玩家 ID 或明確的 anonymous、操作、結果、request ID 與計算值。
24. Log 不得包含 credentials、session、OAuth 資料、cookie、secret 或未處理的原始輸入。
25. 本需求不增加 Equipment、Item instance、戰鬥耗損或耐久修復。
